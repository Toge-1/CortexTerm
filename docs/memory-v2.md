# Memory V2：证据、经验与按需回忆

这是一套可切换的跨会话记忆。它把公开对话/工具事件持久化，再按需搜索历史；可选地调用模型提取经验、修正旧结论。**代码可运行，不等于已经证明复杂记忆能提高真实仓库修复率。** 实验结论另见 `docs/memory-v2-evaluation.md`。

## 启动

```powershell
# 不额外调用模型：搜索过去在此工作目录积累的公开事件、显式记忆
cortexterm --memory raw

# 实验模式：额外做后台提取，每个进程最多 30 次提取调用
cortexterm --memory hybrid --memory-extract

# 回到原来的记忆实现 / 完全不注入记忆
cortexterm --memory legacy
cortexterm --memory off
```

默认仍是 `legacy`，不擅自迁移用户的使用习惯或增加模型账单。上述开关只影响本次启动；要长期启用，在 `%USERPROFILE%\.cortexterm\settings.json` 的原有内容中增加：

```json
{
  "memory": {
    "mode": "raw",
    "autoExtract": false,
    "maxExtractionCalls": 30,
    "maxTokens": 2400,
    "graph": false
  }
}
```

`hybrid` 可以使用之前提取好的经验而关闭 `autoExtract`。`graph` 是实验开关，不能因为图看起来复杂就认定有用。检索预算是现有估算器的 token 估计，不是服务端精确分词值。

## 实际运行的链路

1. **每轮公开事件留档。** `run_agent_turn()` 包装器创建 TurnRecorder。模型的公开回复、工具调用、工具结果获得稳定事件 ID。压缩换掉上下文列表后，记录器仍继续记录新增事件；不记录隐藏思考块或反复注入的系统提示词。
2. **本轮结束或异常时入库。** 原始公开事件与处理队列同一次 SQLite 写入，数据库在 `%USERPROFILE%\.cortexterm\memory-v2\memory.sqlite3`。这是独立的持久化证据，不依赖 session 自动保存何时发生。尚未结束的一轮仍存在内存里，强制杀进程会丢掉这一轮尚未入库的记忆，不能称为逐事件 WAL。
3. **可选后台提取。** 工作线程领取本工作目录的任务，网络调用期间不持有数据库事务。模型最多提出四条经验，并提供原文中的准确引文；程序验证事件 ID、引文和更新目标。失败保留原文、标记失败，后续可手动重试，不阻塞主 Agent。
4. **修正旧知识。** 新记录可以 `supersedes` 旧记录；一个事务中写入新结论、标记旧结论失效、记录更新关系。自动提取不能覆盖显式 `remember` 写入的记忆。原文和旧记录不删除。
5. **下次提问时检索。** TUI 在后台线程刷新 system prompt，先按仓库/工作目录/作用域过滤，再查询原文片段、经验正文和关键词，按排名融合；最多注入约定预算，模型还能 `memory_search`、`memory_read` 查细节。

这里没有假装做了“永远正确的事实库”。引文匹配只能证明出处真实，不能证明提取的结论一定正确，更不能把 assistant 自称测试成功当作客观验证。

## 为什么这样分

| 部分 | 做什么 | 防什么问题 |
|---|---|---|
| `turns` | 公开事件、时间、会话 ID、提取任务状态 | 摘要丢细节后无从追查 |
| `memories` | 陈述、关键词、实体、出处、作用域、状态和版本 | 所有内容都挤在一段 MEMORY.md |
| `links` | 修正关系、同作用域共享实体的关联 | 不知道经验如何变化、不能试验一跳关联 |
| 检索上下文 | 针对当前问题临时生成的短片段 | 启动时无差别塞入全部记忆 |

这版没有另造一个需要同步的 `MEMORY.md` 索引。短目录由查询实时生成，数据库负责持久化，旧版 JSON 只做幂等导入且原文件保留。它与之前讨论的三层思路一致，但具体存储做了取舍。

## 四种策略

- **legacy**：原版 MemoryManager。
- **off**：不注入记忆，不捕获 V2 历史；显式旧版 remember 仍可写盘。
- **raw**：对公开原文的重叠片段做 BM25，另加显式/导入记忆；不会为了排名而调用模型。这是复杂版本必须打赢的基线。
- **hybrid**：原文 + 提取的经验正文 + 提取的关键词/实体，按 RRF 融合。模型提取的中英文别名可以缓解部分用词差异，但不是无限制的语义理解。

可选 `graph` 只扩展一跳共享实体的记忆，并重新检查词项相关性、作用域和状态。保留了注入 embedder 的代码接口，但**没有默认 embedding 服务、没有实测向量检索收益**；当前混合检索不应宣称为“向量 + BM25”。

## 时间、作用域与旧经验

- `user`：同一操作系统用户的跨项目记忆；`project`：共享 Git common directory 的仓库；`local`：本工作目录。自动提取默认 local，避免把工作区临时经验传播到其他仓库。
- 原始会话始终 local，不因两个 worktree 共享 Git 仓库就泄漏过去的对话。
- 支持明确日期以及“今天 / 昨天 / 前天 / 昨晚”和对应英文的日期路由。时间范围先过滤，所以“昨天晚上让我做什么”不要求与过去任务有相同关键词。
- 这个日期是**事件记录时间**，不是从“上个月发布了”中推理出的现实发生时间；任意复杂时间表达并未实现。
- 已 `superseded` 的结构化记录不参与默认检索，但可以按 ID 追溯。原文搜索可能返回当时的旧说法，输出带日期，并提示按当前代码/较新纠正判断。
- 可附带文件哈希的记录在文件变更后不再默认召回；当前没有自动扫描/总结整个仓库的功能。

## 审批、失败与并发

`remember` 仍调用现有 `PermissionManager.ensure_edit()`，允许后才写库；提供 `supersedes` 时审批预览包含旧 ID，替换不允许跨作用域。读工具只返回当前允许作用域内的记录。自动历史捕获与后台提取由用户选择的启动模式启用，属于会话记忆流程，不逐条弹审批。

每个数据库操作使用独立连接，短事务、WAL、忙等待超时；领取任务使用 `BEGIN IMMEDIATE`。任务带租期和 attempt，过期后可恢复，失去所有权的旧工作线程不能覆盖新线程提交的结果。更新记忆还校验旧版本，避免并发合并覆盖。不要把数据库放在不支持正常 SQLite 锁语义的网络共享目录。

退出时最多等待后台线程一秒，不拖住 TUI 退出；未完成任务由下次启动恢复。失败任务最多三次领取，`process --retry-failed` 显式重试。敏感字段和常见密钥形式会被过滤，这不是对任意机密内容的完整识别器。

原始轨迹暂不自动删除，磁盘会随使用增长；**上下文有预算，不代表磁盘无限增长已经解决**。先保留证据，后续可在真实使用量明确后增加按会话归档/导出策略。

## 查看与诊断

TUI 内输入 `/memory` 查看当前策略、队列和提取状态。在项目目录执行：

```powershell
python -m cortexterm.memory_v2 status
python -m cortexterm.memory_v2 search "昨天晚上做了什么"
python -m cortexterm.memory_v2 search "审批 event clear" --mode hybrid --graph
python -m cortexterm.memory_v2 read <memory_id>
python -m cortexterm.memory_v2 process --max-calls 5 --retry-failed
```

`status/search/read` 不调用模型；`process` 会调用已配置的 API。可以指定 `--project <目录>` 和 `--db <数据库>`（放在子命令之前），方便隔离实验。
