# 统一记忆系统：历史、经验与按需回忆

想先看清各功能的作用、触发条件和调用流程，请打开 [图文设计说明（离线 HTML）](memory-v2-design.html)。包含 5 张流程图、完整对话示例、BM25 计算示例、后台任务状态和源码索引。

启动即使用这套跨会话记忆：保存公开对话/工具事件，后台提取经验、修正旧结论，模型需要时搜索。用户无需选择版本。**这是产品取舍，不等于实验已经证明它提高了真实仓库修复率。** 历史实验结论另见 `docs/memory-v2-evaluation.md`。

## 当前查询规则（2026-10-21 调整）

| 用户要做什么 | 模型给工具的参数 | 程序执行什么 | 返回什么 |
|---|---|---|---|
| 查话题，如“测试为什么失败” | 非空 `query` | 可见、有效经验与历史片段一起计算一次 BM25 | 匹配片段/经验、分数、出处 ID |
| 翻历史，如“昨晚聊了什么” | 空 `query` + 两个时间边界 | 只查 `turns`，按记录时间和 ID 升序分页 | 每轮的用户问题、时间、ID、`next_cursor` |
| 查某时段的话题 | 非空 `query` + 两个时间边界 | 先筛时间，再执行同一次 BM25 | 只返回有文字匹配的结果 |

**已取消 RRF 和时间排名加分。** 一条经验只构造一个“正文 + 关键词 + 实体”搜索文本；原文按消息切片后搜索，不把整轮原文另外加入话题排名。同一事件中命中同一原文位置的重叠片段合并，保留最高 BM25 分，不累加；不同位置的事实不因来源相同而删除。纯时间查询不混入经验，不产生相关性分数（`score: null`）。

搜索默认每次返回 5 条。历史页有 `next_cursor` 时，模型继续传相同时间范围、空 `query` 和该游标，直到游标为空。游标绑定工作目录与时间范围；按 `(recorded_at, id)` 继续，避免同一时间的多轮对话被跳过。历史页只预览用户问题；要看 Agent 的回复和结果，再 `memory_read(turn_id)`。

## 启动

```powershell
cortexterm
```

不需要记忆启动参数。固定执行：历史留档、后台经验整理、按需工具检索；不会每轮自动塞入旧记忆。后台整理会使用已经配置的模型接口，提取和比较共用每进程最多 30 次调用的默认预算。没有模型配置或预算耗尽时，历史和已有经验仍可查询，待整理任务留存。

只有需要调整费用预算时，才在 `%USERPROFILE%\.cortexterm\settings.json` 原有设置中添加下面这一项。设为 0 会暂停额外的后台模型调用，保存和检索不变：

```json
{
  "memory": {
    "maxExtractionCalls": 30
  }
}
```

旧配置中的 `mode`、`autoExtract`、`autoRecall`、`graph` 已不再决定产品行为，不需要清理这些字段才能使用。旧 JSON 记忆会幂等导入 SQLite，原文件不改写。数据库故障会明确报告，不静默切换成旧版全量上下文注入。

**固定采用按需工具检索。** 模型可调用 `memory_search` / `memory_read`，用户不用手动翻数据库。历史实验里的自动预注入没有稳定改善修复，因此产品不提供这个策略选择；这也不等于按需策略已经被证明修复率更高。

对 `api.deepseek.com` 的后台提取请求，默认显式关闭 thinking，防止有限输出预算全部消耗在思考而没有 JSON；主编码 Agent 不受影响。可用 `memory.extractionThinking: "provider-default"` 恢复提供方默认值，其他提供方保持原设置。依据是 [DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/) 与 [Anthropic 兼容接口](https://api-docs.deepseek.com/guides/anthropic_api/)；本项目还做了真实请求复测。

## 实际运行的链路

1. **每轮公开事件留档。** `run_agent_turn()` 包装器创建 TurnRecorder。模型的公开回复、工具调用、工具结果获得稳定事件 ID。压缩换掉上下文列表后，记录器仍继续记录新增事件；不记录隐藏思考块、系统提示词或程序自动生成的重试/继续指令，防止把它们误当成用户偏好。
2. **本轮结束或异常时入库。** 原始公开事件与处理队列同一次 SQLite 写入，数据库在 `%USERPROFILE%\.cortexterm\memory-v2\memory.sqlite3`。这是独立的持久化证据，不依赖 session 自动保存何时发生。尚未结束的一轮仍存在内存里，强制杀进程会丢掉这一轮尚未入库的记忆，不能称为逐事件 WAL。
3. **后台提取。** 有模型配置和调用额度时，工作线程领取本工作目录的任务。程序将本轮材料划成不超过 1,000 字符的片段，尽量沿换行切分并编号。第一次模型调用只看本轮材料，最多提出四条候选，同时选择 `scope` 和 1–8 个 `evidence_ids`，可以跨消息选片段。模型不抄写引用、不计算字符位置。程序检查编号确实在给定材料中，把候选保存到 `turn_candidates`；空候选直接完成。原有单消息 6,000 字符和整轮约 24,000 字符的输入预算仍然生效，因此模型只能选择本次提供的片段。
4. **用候选找旧经验，再决定如何更新。** 用候选正文、关键词和实体搜索有效旧经验。同一 scope、仓库和工作目录的记录可被替代，包括以前 remember 写的记录；更宽范围的记录只供去重参考，各组分别取 BM25 前 8 条。窄范围的同文记录不能阻止保存宽范围经验。没有旧命中直接新增；否则模型比较后返回 `ADD / NOOP / SUPERSEDE`。程序根据选中片段的位置从原消息取得 `quote`，交给比较模型，不做模型摘抄的逐字符匹配。NOOP 必须指定已有记录，SUPERSEDE 不能跨作用域。记录更新、旧记录失效、处理结果和任务完成同一事务提交。
5. **下次需要时检索。** 由模型调用 `memory_search`、`memory_read`，按本页开头三种规则执行。工具结果通过正常 Agent Loop 进入下一次模型请求。

一轮首次正常处理使用 1 次提取调用，必要时再使用 1 次比较调用；失败后人工重试可能产生额外调用。两阶段共用 `maxExtractionCalls` 预算。预算在两阶段之间耗尽时保留候选、把任务放回 pending，不消耗失败次数；下次有预算时从比较阶段继续。比较失败也保留候选，重试时重新查旧经验，避免再次提取原文。网络调用期间不持有数据库事务。

每次主 Agent 请求模型前，程序注入本会话最近三轮的后台状态：待处理、运行中、失败，或已提交的新增/跳过/替代结果（含记忆 ID、scope、内容预览和目标 ID）。这个临时状态计入上下文预算，不写入对话历史，也不会被再次提取。它不是全量记忆列表；查更早的经验仍用 memory_search/read。后台没完成时不能声称已保存。

经验记录保存来源消息 ID 和片段位置，不重复存原文。memory_read 读取经验时由程序补出 quote；也能按片段 ID 读引用、按消息 ID 读完整原消息。来源存在不等于经验正确，选错片段、选错 scope 或误判语义仍可能发生。

## 为什么这样分

| 部分 | 做什么 | 防什么问题 |
|---|---|---|
| `turns` | 公开事件、时间、会话 ID、提取任务状态 | 摘要丢细节后无从追查 |
| `memories` | 陈述、关键词、实体、出处、作用域、状态和版本 | 所有内容都挤在一段 MEMORY.md |
| `turn_candidates` | 已校验的第一阶段提取结果 | 比较失败或预算耗尽后重复提取 |
| `links` | 修正关系、兼容保留的共享实体关联 | 不知道经验如何变化；关联不参与排名 |
| 检索上下文 | 针对当前问题临时生成的短片段 | 启动时无差别塞入全部记忆 |

这版没有另造一个需要同步的 `MEMORY.md` 索引。短目录由查询实时生成，数据库负责持久化，旧版 JSON 只做幂等导入且原文件保留。它与之前讨论的三层思路一致，但具体存储做了取舍。

## 一套查询实现

经验（含显式保存、旧版导入、后台提取）和历史片段统一搜索。每条经验把正文、关键词、实体组成一个搜索文本，只计算一次 BM25。仓库内部保留的旧类与评测对照参数用于导入/历史实验，不是用户需要选择的产品版本。

搜索不调用模型、embedding 或图扩展。BM25 仍是字面匹配；模型提取的中英文关键词可以缓解部分用词差异，但不能保证语义相近的问题一定命中。历史评测报告中的 RRF/graph 指旧实现，不代表本次改动后的效果；原报告保留，不改写成绩。

## 时间、作用域与旧经验

- `user`：同一操作系统用户的跨项目偏好；`project`：共享 Git common directory 的仓库约定；`local`：本工作目录及环境。提取模型在同一次调用中判断范围，依据不明时用 local；程序校验枚举和数据库归属，无法证明模型判断一定正确。
- 原始历史浏览仍然 local。可见的共享经验允许按其来源 ID 读取所引用的原消息，不允许顺便读取原目录里的其他消息或整轮历史。
- 时间范围由**主 Agent 模型理解用户语义后填写**，不再用正则从搜索文本猜日期。每次主模型请求前都会更新带 UTC 偏移的本地时间上下文，模型据此把“上周三下午”等表达转换成 `start_time` / `end_time`。这沿用本轮正常模型调用，不增加单独的时间解析 API 请求；含糊不清的日期应先询问用户。
- `memory_search` 接受 `query`、`start_time`、`end_time`、`limit`、`cursor`。两个时间参数必须同时提供，为带时区的 ISO 8601 时间戳，采用 `[start_time, end_time)`；缺时区、无效日期、倒序或不完整范围会报错。`query` 可为空或省略，此时只分页浏览原始历史；非空时执行统一 BM25，时间只过滤、不加分。`cursor` 仅用于空查询的后续历史页。只传 `query` 时不应用隐含日期过滤。
- 时间过滤依据 **turn 开始的记录时间 / 经验的记录时间**，不是文字中描述的现实事件时间；例如“今天提到去年发布的版本”仍是今天记录的内容。一轮跨过午夜，原始 turn 仍按开始时间归属。模型理解自然语言的准确性并未由参数校验保证；模型需要时间范围时使用工具显式查询。
- 已 `superseded` 的结构化记录不参与默认检索，但可以按 ID 追溯。原文搜索可能返回当时的旧说法，输出带日期，并提示按当前代码/较新纠正判断。
- 可附带文件哈希的记录在文件变更后不再默认召回；当前没有自动扫描/总结整个仓库的功能。

## 审批、失败与并发

主 Agent 不再注册 `remember`，唯一正常写入流程是轮末后台提取，不逐条弹审批。主 Agent 通过 memory_search/read 查询结果；旧记忆保留可读。后台替代必须在同一作用域，不能用某个目录的例外覆盖全局约定。

每个数据库操作使用独立连接，短事务、WAL、忙等待超时；领取任务使用 `BEGIN IMMEDIATE`。任务带租期和 attempt，过期后可恢复，失去所有权的旧工作线程不能覆盖新线程提交的结果。更新记忆还校验旧版本，避免并发合并覆盖。不要把数据库放在不支持正常 SQLite 锁语义的网络共享目录。

NOOP 所依据的旧记录也要在提交时检查版本和 active 状态。如果模型比较期间旧记录已经被别的进程替代，就保留候选并报告本次失败，不能依据已经失效的旧内容默默丢掉新候选。

退出时最多等待后台线程一秒，不拖住 TUI 退出；未完成任务由下次启动恢复。失败任务最多三次领取，`process --retry-failed` 显式重试。敏感字段和常见密钥形式会被过滤，这不是对任意机密内容的完整识别器。

原始轨迹暂不自动删除，磁盘会随使用增长；**上下文有预算，不代表磁盘无限增长已经解决**。先保留证据，后续可在真实使用量明确后增加按会话归档/导出策略。

## 查看与诊断

TUI 内输入 `/memory` 查看当前策略、队列和提取状态。在项目目录执行：

```powershell
python -m cortexterm.memory_v2 status
python -m cortexterm.memory_v2 search --start-time "2026-10-20T18:00:00+08:00" --end-time "2026-10-21T00:00:00+08:00"
python -m cortexterm.memory_v2 search "审批 event clear"
python -m cortexterm.memory_v2 search --start-time "2026-10-20T18:00:00+08:00" --end-time "2026-10-21T00:00:00+08:00" --cursor "上一页的 next_cursor"
python -m cortexterm.memory_v2 read <memory_id>
python -m cortexterm.memory_v2 process --max-calls 5 --retry-failed
```

`status/search/read` 不调用模型；`process` 会调用已配置的 API。可以指定 `--project <目录>` 和 `--db <数据库>`（放在子命令之前），方便隔离实验。

话题结果的 `score` 是 BM25 值，不是可信度。结果还带 `result_type`、scope、时间、命中词、来源 ID 和围绕命中处截取的短文本。`memory_read(chunk_id)` 只读该片段；`memory_read(event_id)` 读完整消息；`memory_read(turn_id)` 读整轮。长 read 输出仍按 `next_offset` 分页。

## 版本与回退

当前开发分支 `codex/memory-v2`。版本回退通过 Git 提交或改动备份完成，不再提供运行时版本选择。原 JSON 与 Session 文件没有被重写。不要用强制 reset 丢弃工作区里其他未提交的文件。
