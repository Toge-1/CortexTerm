# Memory V2 的验证与取舍

**目前没有证据证明复杂记忆提高了 CortexTerm 的真实仓库修复率。** 已实现可追溯记录、隔离检索、后台提取和修正关系；自动预注入与关联扩展保留为实验开关，默认使用记忆工具按需检索。原版仍可直接使用。

[打开交互报告](evidence/memory-v2-20261020/pilot/index.html) · [原始/复核数据与校验清单](evidence/memory-v2-20261020/README.md)

## 工程正确性

最终代码全套 **357 passed，3 skipped**。其中 `tests/test_memory_v2.py` 包含 30 项检查，覆盖：

- 同作用域搜索与直接读取隔离、旧记录可追溯；
- 原文持久化、事件 ID 稳定、重复入库幂等；
- 时间查询、未来信息排除、长日志尾部命中、预算控制；
- 事务内更新、并发领取、过期租约、失去所有权的旧线程不能覆盖结果；
- 模型编造引文被拒、失败保留原文、提取调用额度用尽后保持 pending；
- 显式 remember 审批、即时可见、不能跨 scope 替换；
- Agent Loop 真正的工具调用/结果捕获、异常路径捕获；
- `/memory` 统计、按出处 ID 打开原始事件、自动预注入必须显式开启。

这些测试证明具体机制按约定工作，**不证明模型因此修复更多 bug**。

## 编码迁移小样本

代码：`benchmarks/memory_v2_eval.py`，冻结实现 `d0824cc`。数据由本次开发构造，包含 6 个问题，每题 2 次、5 组，共 60 次 Agent 执行。

五组分别是：无记忆、完整历史、原文 BM25 搜索、提取经验混合搜索、提取经验加一跳实体关联。每组使用相同历史、模型、初始文件、最大 5 步及 2400 估算 memory tokens。模型为当前配置的 `deepseek-v4-pro`，单次输出上限 1800，关闭 API 重试；provider 未保证固定 seed。完整历史在这个小数据集内能完整装入共同预算，没有故意截坏这个基线。

每次恢复初始文件，组内顺序打乱。历史提取不读取目标任务、代码或隐藏测试。模型通过实际 `run_agent_turn()` 调用读写工具，外部 Python 进程执行隐藏断言。没有使用 LLM judge。

2026-10-20 跑完后的结果如下。每组 12 次是六道题各做两次：

| 策略 | 原始判定 | 统一复核后 | Agent 模型调用 | 累计秒数 |
|---|---:|---:|---:|---:|
| 无记忆 | 2/12 | 2/12 | 56 | 944.246 |
| 完整历史 | 11/12 | 12/12 | 41 | 248.507 |
| 原文搜索 | 9/12 | 11/12 | 43 | 310.287 |
| 提取经验混合搜索 | 11/12 | 12/12 | 40 | 250.026 |
| 混合搜索 + 关联扩展 | 10/12 | 12/12 | 41 | 216.762 |

经验提取另用了 **43 次调用、551.930 秒、42,887 个输出 token**，其中一次因输出预算耗尽失败；它不包含在表里的 Agent 耗时中，不能漏算。原文搜索和完整历史不需要这部分调用。

十二次图扩展的 graph 通道均为空，没有额外候选，**这一集没有实际检验关联扩展的增益**。混合搜索与 graph 行的耗时差不能归功于图。完整历史在此已经 12/12，复杂版本没有超过这个强基线。

这里的限制很实质：

1. 部分任务的私有接口约定仅存在于历史，冷启动失败不能解释成一般编码能力差。
2. 1800 的输出上限也限制了 DeepSeek 的思考；部分运行耗尽输出/步数而没有改文件。结论只适用于这组预算。
3. 原文与提取内容并非两个独立信息源，不能把混合搜索胜出直接归因于“图”或“语义”。
4. 六题各重复两次仍只有六个任务，不是十二个独立问题；不报告显著性结论。
5. 使用定制的读写工具子集，没有测完整命令环境、复杂依赖、真实 SWE-bench 仓库。
6. 最终交付的默认策略是按需工具检索；这个实验测的是强制预注入，不是默认策略的总体成绩。

### 判定复核

审批题原断言要求 `decision` 键不存在，错误地拒绝了把旧值清为 `None` 的正确实现。题面要求“不泄漏旧审批结果”，并未要求一定删除字典键。

统一改为 `result.get("decision") is None` 后，`memory_v2_audit.py` 使用**已经生成并保存的代码**重判所有组，没有重新生成答案。原始 `runs.jsonl` / `report.json` 不改，复核结果单独保存为 `runs.audited.jsonl` / `report.audited.json`。冻结数据文件、两版断言和哈希均保留。

新版本的题目源文件已经修正这条断言，未来运行无需执行旧数据专用的 audit。

第一轮 8 步预算时，三组均为 0/2，轨迹显示还在读文件就耗尽步数，因此没有拿这轮结果当作记忆效果结论。第二轮统一提供文件清单、16 步预算和 4000 输出上限；当前表格是第二轮，冻结代码 `9820b65`：

| 策略 | 通过 | 两题累计耗时 |
|---|---:|---:|
| 无记忆 | 2/2 | 182.879 秒 |
| 原文预注入 | 1/2 | 118.100 秒 |

**失败组用时较短不能称为效率更高。** 这轮失败均未在步数限制内完成有效修复；轨迹中能看到大量源码读取。只有两题、每组一次，不能据此断言“记忆必然有害”，但它确实不支持把自动预注入默认开启。

历史线索是依据项目知识构造的笔记，不是按真实时间顺序恢复的历史会话。这两题是实际仓库/既有测试上的集成回放，也不是公开 benchmark 的正式结果。

## 从失败中修掉的实现问题

- 提取响应有时只有 thinking，没有 JSON：DeepSeek 默认思考消耗完了 2400 输出额度。只对这个已核实的提供方，后台提取显式关闭 thinking，主 Agent 保持原设置。
- 对两个先前截断的输入复测，均得到可解析响应：一个保存了两条经验，另一个返回空候选。分别消耗 387 和 6 个输出 token；这是定点复测，不冒充全套新版本的端到端重测。
- 提取预算耗尽时不把未处理历史标成失败；任务保留 pending。
- 提取线程失去租约后不能覆盖新线程的结果；最后一次领取后崩溃会转为可见的 failed 状态。

参数依据：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[Anthropic 兼容接口](https://api-docs.deepseek.com/guides/anthropic_api/)。

## 交付策略

保留 SQLite 证据库、时间查询、原文分块检索、出处追溯、旧知识修正与按需记忆工具。后台模型提取、自动预注入、关联扩展分别可以开启，**没有因为它们看起来复杂就认定更强**。

向量检索仅保留注入接口，没有配置默认 embedding 服务，也没有用它声称“语义检索提升”。同样没有声称复现某篇论文结果或提高了 SWE-bench resolved。

如果继续研究有效性，下一步应冻结多仓库、按真实时间划分的历史任务；比较无记忆、完整历史、原文搜索、模型主动检索、预注入，并给所有组充分且相同的编码预算。这需要新的评测，不是给当前六个小题再增加重复次数。

## 复现

运行下面两条会真实调用已配置 API；输出目录必须是新目录：

```powershell
python -m benchmarks.memory_v2_eval --output artifacts/my-memory-pilot --repeats 2
python -m benchmarks.memory_v2_repo_eval --output artifacts/my-repo-replay
python -m benchmarks.memory_v2_report artifacts/my-memory-pilot --repo-dir artifacts/my-repo-replay
```

公开轨迹不包含 API key 或隐藏思考内容。报告保留服务端的 usage 字段；缓存输入单独列出，不使用未经核实的价格估算金额。数据、源码、工具输出和判定日志可以逐条核对。

HTML 做了脚本语法和数据一致性检查。内置浏览器安全策略拒绝 `file://` 导航，因此没有完成截图式视觉验收；可在本机直接打开这个离线文件查看。
